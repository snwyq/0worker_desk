# 0worker_desk

`0worker_desk` 是一款面向中文运营团队、内容工作室、个人创作者与多账号操盘场景的本地化 AI 内容分发 Agent 工具。它的目标不是只做“发帖器”，而是围绕 “AI 生成内容 -> 任务编排 -> 多账号投放 -> 指纹浏览器隔离 -> 风控人工接管 -> 结果追踪” 这一整条链路，提供更符合中国用户实际工作方式的桌面操作系统。

当前版本聚焦微博多账号发布 MVP，同时在架构层已经为小红书、公众号、抖音图文、知乎、B 站动态等多平台分发能力预留了统一扩展接口。

## 产品定位

在中国内容分发场景里，真正难的通常不是“把一段文字发出去”，而是下面这些更贴近实战的问题：

- AI 生成的内容需要进入一个可审阅、可调度、可分发的工作流，而不是停留在聊天窗口里。
- 同一个平台往往需要多个账号同时运营，但每个账号又必须隔离环境、隔离指纹、隔离登录态。
- 发布动作不能只靠人工逐条处理，需要有队列、计划任务、异常标记与重试机制。
- 平台风控、登录失效、验证码、上传失败等情况必须能被及时识别，并切换回人工接管。
- 对中文用户来说，工具需要优先适配“多账号运营、内容矩阵、私有部署、本地数据可控”的实际需求。

`0worker_desk` 正是为这些问题而设计。

## 核心能力

### 1. AI 内容进入分发工作流

- 支持将待发布内容以任务形式录入本地系统，而不是零散保存在聊天记录中。
- 支持为内容绑定目标账号、发布时间、媒体文件和状态流转。
- 支持把 AI 生成内容纳入“草稿 -> 排队 -> 发布中 -> 已发布 -> 失败 -> 人工处理”完整链路。

### 2. 同平台多账号矩阵分发

- 支持同一平台下维护多个账号。
- 每个账号可独立配置连接方式、状态、备注和运行策略。
- 适合内容矩阵运营、工作室批量分发、品牌多账号协同等场景。

### 3. 指纹浏览器接入与账号隔离

- 支持通过已打开的浏览器自动化连接信息接入账号环境。
- 当前已支持：
  - `manual_ws`：手动填写 Chrome DevTools WebSocket 连接地址
  - `manual_port`：手动填写本地调试端口
  - `adspower`：AdsPower 指纹浏览器接入基础能力
- 架构已预留：
  - `bitbrowser`
  - `gologin`
  - 其他具备本地 API / CDP 能力的指纹浏览器

这意味着系统从一开始就不是为“单浏览器单账号”设计，而是为“账号隔离、环境隔离、指纹隔离”的运营模式设计。

### 4. 调度发布与任务轮询

- 支持发布队列管理。
- 支持定时任务轮询处理到期内容。
- 支持立即发布与到点发布两类操作。
- 支持本地调度器持续检查待执行任务。

### 5. 发布过程控制

- 发布前校验账号状态与任务状态。
- 支持连接浏览器环境后执行页面级自动化操作。
- 已包含微博 Web 发布流程相关发布器模块。
- 支持媒体文件选择与随内容一并处理。

### 6. 异常识别与人工接管

- 能识别账号不存在、连接失败、登录失效、需要人工操作等状态。
- 可将失败任务标记为 `failed` 或 `needs_manual_action`。
- 当检测到登录页、验证页、人工风险介入场景时，可停止自动流程并交回人工处理。

### 7. 本地化数据与运行安全

- 数据本地保存，不依赖第三方 SaaS 后台。
- 不以托管账号密码为设计前提。
- 不绕过平台登录、验证码或风控校验。
- 更适合重视数据可控、环境可控、部署可控的中文团队。

## 平台扩展路线

虽然当前 MVP 重点在微博，但整体设计并不局限于微博。项目的目标形态是构建一个统一的内容分发 Agent 中台，为多个平台复用相同的调度、账号、日志、人工接管与浏览器连接能力。

后续适合扩展的平台包括：

- 小红书
- 微信公众号后台
- 知乎
- B 站动态
- 抖音图文/企业号运营后台
- 视频号相关后台发布场景

推荐扩展方式是保留统一的：

- 账号模型
- 内容任务模型
- 浏览器连接器接口
- 平台发布器接口
- 调度与日志系统

然后按平台分别实现发布器，而不是为每个平台单独再造一套系统。

## 典型使用场景

- AI 批量生成文案后，进入人工审核，再分发到多个账号
- 同一篇内容拆分不同版本后投放到多个运营账号
- 工作室统一管理多个指纹浏览器账号环境
- 运营团队进行定时发布、错峰发布、人工补发
- 内容矩阵项目进行平台化、标准化分发管理

## 系统结构

当前项目主要由以下部分组成：

- `electron/`
  - Electron 主进程与预加载脚本
- `src/main/`
  - 浏览器连接器
  - 本地数据库
  - IPC / HTTP 接口
  - 发布服务与调度器
  - 微博发布器
- `src/renderer/`
  - 桌面前端页面
- `src/shared/`
  - 前后端共享类型
- `tests/`
  - 单元测试与集成测试
- `docs/`
  - 设计文档与实现规划

## 环境说明

如需使用 AdsPower 相关能力，需要准备本地可访问的 AdsPower 运行环境，并按项目约定配置：

- `ADSPOWER_API_KEY`

如果只使用手动 `wsEndpoint` 或 `debuggingPort` 方式，则不依赖 AdsPower。

## 设计原则

这个项目遵循以下原则：

- 优先服务中文用户真实运营场景
- 优先本地化与私有化能力
- 优先多账号隔离与指纹浏览器协同
- 优先任务编排和人工接管，而不是“黑盒一键群发”
- 优先可扩展架构，而不是只为单平台写死逻辑

## 项目愿景

`0worker_desk` 的长期目标，是成为一个真正适合中国内容运营者使用的 Agent 工作台：

- 上游能接入 AI 生成内容
- 中间能进行审核、改写、排程、分账号编排
- 下游能连接多个平台与多个账号环境
- 遇到风控时能及时切换人工处理
- 最终形成一个稳定、可控、可扩展的内容生产与分发闭环

如果你正在寻找的不是一个简单“自动发帖脚本”，而是一套更接近中国内容团队真实使用方式的本地分发 Agent 工具，那么这个项目就是朝着这个方向构建的。
