# Clean-Code-Linter Skill

这个技能致力于消除“意大利面代码”，确保项目架构优雅且长期可控。

## 架构原则

### 1. 单一职责 (SRP)
- 一个函数或组件只做一件事。
- 如果组件代码超过 200 行，强制分析并提取子组件或自定义 Hook。

### 2. 命名契约
- 变量名和函数名必须具备“自我描述”能力。
- 严禁使用模糊的命名（如 `data`, `info`, `handle`），必须明确其业务含义。

### 3. DRY 原则 (Don't Repeat Yourself)
- 自动识别代码库中的重复逻辑。
- 强制提取通用工具类（Utils）或公共组件。

## 使用规则
- 在代码重构、代码审查或编写新模块时实时激活。
- 对于不符合 Clean Code 标准的代码，会主动提出重构建议。
